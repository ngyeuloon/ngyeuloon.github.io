Framework 01

Data Journey Monitoring Alert Framework

THE PROBLEM BEFORE DJMAF

Data landing in the data lake wasn't reconciled. Nothing compared what left the source against what arrived. In practice that meant our first warning was a Tableau user or someone on the visualization team noticing that a number looked wrong and raising it with us.

By that point the issue was already downstream. We would correct it after the fact, and it consistently delayed month-end.

Reconcile it before anyone has to notice

Python · SQL · ServiceNow · xMatters

DJMAF
  • Pre-ingestion: compares the incoming source data structure against the ADW table structure before anything is loaded.
  • Reconciliation: a source count check and a target count check across the data journey. This is the core of the framework and always runs.
  • Post-ingestion: duplicate and null-count checks on what actually landed.
  • Pre- and post-ingestion checks are configurable per project and can be switched off from a commands.txt file, so a pipeline only pays for the checks it needs.
  • Every run writes its outcome to a single results table the data analyst team reads directly, instead of asking us.
  • Any failed check POSTs to ServiceNow to raise a Priority 3 incident, which triggers xMatters to call the on-call developer.
  • Dynamic queries handle the joins and aggregations, so the checks work across tables without being rewritten each time.

IMPACT  Incidents raised by the visualization team fell by 50%, and month-end was no longer delayed by data issues found late.

Context

The platform all three run on

None of these frameworks stand alone. They're the ingestion and assurance layer of a corporate data lake house on OCI. Data arrives over APIs, as GFT files, through direct database connections, and by real-time Golden Gate sync. It lands in the Stage and Raw zones in ADW, is curated into domain tables, and flows out to the reporting layer and to outbound consumers.

Governance wraps all of it — quality checks, access policy, and Kerberos authentication between the lake and everything that reads from it. DJMAF is the assurance that runs across that whole journey, from the source systems on the left through to the curated tables the reporting layer depends on.
